# Two-table INNER, LEFT, and RIGHT JOIN

```sql
SELECT s.name, e.course
FROM students AS s INNER JOIN enrollments e ON s.id = e.student_id
WHERE s.age >= 18
ORDER BY e.course, s.name
LIMIT 10;
```

JOIN, INNER JOIN, LEFT [OUTER] JOIN, and RIGHT [OUTER] JOIN are accepted.
Table aliases may use AS or be implicit,
including on single-table queries. An alias hides the underlying table name.
Self joins require distinct qualifiers. Unqualified names must identify exactly
one input column; ambiguity is rejected in SELECT, ON, WHERE, and ORDER BY.
Names remain case sensitive. Column aliases and table.* are unsupported.

The first version accepts exactly one ON equality between columns on opposite
sides with matching INTEGER or STRING types. Reversed operands work. Compound
ON predicates, non-equality joins, FULL joins, comma joins, and more than two
table references are unsupported. WHERE filters the join result; it is not
equivalent to adding an ON condition on the nullable side of an outer join.

The planner binds against a combined schema: all left columns, then all right
columns. Projection, filtering, and sorting use that layout. SELECT * expands
both schemas in this order; output labels retain original names, including
duplicates. All matching pairs are emitted, preserving duplicate multiplicity.
There is no guaranteed SQL result order without ORDER BY.

Executor builds NestedLoopJoinOperator with an outer child and a factory for fresh
inner subtrees. INNER/LEFT use the logical left as outer; RIGHT uses the logical
right as outer. Opening the join opens only the outer input. Each outer row starts
a fresh inner scan; no single-use cursor or operator is reopened. Results stream
one pair at a time without materializing either input. For N outer and M inner
rows, worst-case comparisons are N*M and inner scans are N. Extra join memory
is proportional to row width, excluding child buffers and collected QueryResult.

Empty outer inputs never open the inner subtree. An empty inner input is rescanned
for each outer row. Consequently unread inner-side CSV errors are not observed
when the outer side is empty; metadata is still validated during planning.
EOF, explicit close, upstream LIMIT termination, and runtime failures close all
owned children. Cleanup attempts both children and retains secondary failures
as suppressed exceptions. The join is single-use; close is idempotent.

The optimizer currently traverses joins without pushdown or algorithm selection.
Storage interfaces are unchanged. This is the correctness baseline for later
block nested-loop or hash joins; there is no index or page-buffer requirement.

## NULL semantics

LEFT preserves every logical left row; RIGHT preserves every logical right row.
After the inner scan reaches EOF, an unmatched outer row produces exactly one
result padded with typed NULL cells for the missing input. Duplicate unmatched
rows remain separate. RIGHT restores logical left-then-right column order before
evaluating ON and before returning rows, so existing bound indexes remain valid.

Value.raw may be null in query results; its DataType remains INTEGER or STRING.
Comparison with NULL yields UNKNOWN, including NULL = NULL. AND/OR/NOT follow
SQL three-valued logic. WHERE and ON pass only TRUE. IS NULL and IS NOT NULL
always produce TRUE or FALSE. Standalone NULL literals remain unsupported.
NULL values print as NULL and sort last for ASC, first for DESC. Literal STRING
NULL prints as 'NULL'; strings starting with a quote are also quoted and escaped.
Versioned nullable CSV files encode NULL as \N; legacy CSV files retain their
original behavior. An empty STRING field remains an empty string, not NULL.

```sql
SELECT s.name
FROM students s LEFT JOIN enrollments e ON s.id = e.student_id
WHERE e.student_id IS NULL;
```

This finds students without enrollments. A predicate such as WHERE e.course =
'Database' removes null-extended rows. No filter is pushed across an outer join.

tests use the existing JUnit 5 dependency. Supplier, Objects, lists, and streams
are JDK APIs. The following inventory describes the outer-join extension.
Record component accessors/equals/hashCode/toString are generated by Java.

## Execution and lifecycle example

For `a RIGHT JOIN b`, the physical outer is b and the inner factory creates a.
open() opens b only. Each b row gets a new scan of a. Each candidate is combined
as `[a columns, b columns]` and evaluated with the original ON column indexes.
If no candidate matches, the operator closes a and returns `[NULL a, b row]`.
The next call advances b. EOF closes b; explicit close and LIMIT close any active
scan. A failed scan is an error, never evidence that the row is unmatched.
